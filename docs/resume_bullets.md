# 简历子弹与面试短答（有真实数字）

> 数字来源：`data/eval/ablation.json`、`data/eval/result.json`（2026-10-11）  
> 模型：`qwen2.5:3b`（本机）；口径见 ablation `definition`。

## 两条子弹

> 基于 LangGraph 构建固定五段合规预审工作流（场景理解 / 混合检索 / 风险分析 / 证据校验 / 报告生成），步骤之间用 Pydantic Schema 交接；Hybrid RAG 混合检索，校验节点用代码检查引用是否为原文子串，对不上就降级，证据冲突则显式标出。  
> 提供 FastAPI 与 Web 演示（运行轨迹、缺信息补填后续跑、报告下载）。50 条自动用例（含检索 Hit@5=15/15）；同一模型同一批证据的三列对照中，加上校验节点后，引用无法回溯原文的比例从 **74.9%** 降到 **0.0%**。

## 数字怎么跟面试官解释

- **公平性：** 列 B/C 使用同一批风险声明（模型输出 + 1 条探针幻觉），同一证据池；只差「是否跑 verify」。  
- **0.0% 含义：** 校验后仍保留 `evidence_ids` 的条目中，全部能逐字对上原文；对不上的被清空引用并标 `assumption`。  
- **不要说：** 「模型变聪明了」——要说「代码规则挡幻觉」。

## 6 问短答

1. **为什么多步？** 固定状态机保证顺序与可测；校验不调模型，避免「多聊几次假装 Agent」。  
2. **怎么防幻觉？** `evidence_id` 存在且 `text` 为原文子串，否则降级；冲突两边保留。  
3. **和知识库问答区别？** 问答是一问一答；本项目是表单进、结构报告出，中间有独立校验节点。  
4. **评测怎么算？** 检索 Hit@5；不可回溯比例；报告结构/缺信息/禁区主题；三列对照。  
5. **检索错了？** 证据不对则校验失败→assumption/missing，不硬编。  
6. **缺字段？** `hold` 列出 questions，补填后续跑。
